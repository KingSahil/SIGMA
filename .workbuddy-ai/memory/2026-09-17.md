## 符号率与解调：概念梳理（未改代码）

用户在为 SIGMA（SIH 6147）实现流水线阶段 4/5（调制成解调、比特提取），需求是：
先讲清「符号率（symbol rate）」与「解调（demodulation）」是什么、怎么用、有什么价值。

### 结论 / 关键点
- 采样率 f_s（1 Msps）≠ 符号率 R_s。前者是每秒复数样本数，后者是每秒符号数。比值这就是 SPS
  （每符号采样数）。以 `data/iq/bpsk_modulated_1msps.iq` 为例：50,000 样本 @ 1 Msps，
  若 R_s = 50 ksps 则 SPS = 20。
- 符号率无法从文件字节数或采样率推出来，必须实测。现行 `sigma_analyzer_core.py` 算出了 99% 占用带宽
  （OBW）却没有据此换算符号率，这一环是断的。
- 初估关系式：R_s ≈ OBW / (1 + α)，α 为滚降系数（RRC），α ≈ 0.2–0.5。偏保守但只要 α 不虚高就不会低估 R_s。
- 精确测量：对 |x[n]|² 去均值做 FFT，在 f_s/SPS 处出谱线（出现即代表存在符号定时分量）。
- 数字解调的三步：载波恢复（Costas 环，修频偏相位偏移）→ 匹配滤波（根升余弦，最大化 SNR）→
  符号同步（Gardner 或 M&M 误差检测器驱动 Farrow 插值器，取出最佳判决点）→ 判决 + 映射回比特。
- 符号率的价值：区分星座（BPSK/QPSK 与 8PSK/16QAM 常符号率相同、星座不同）、算比特率 R_b = R_s·log2(M)、
  设匹配滤波器带宽、取判决时刻、区分同频段不同体制（GSM 270.833 ksps、DVB-S 等）。
- 无同步的常见现象：星座图会随时间旋转（频偏）或形成模糊环（无定时），与 SIGMA 现有 const_sink 显示一致。
- 用户当前 78.4% 置信度的分类器很可能全靠文件名提示和硬编码阈值，不是真正的特征判别。

### 实测结果（诚实记录）
- **符号率估计：10 个用例中 9 个误差 0.00%**，覆盖 25–250 ksps、α=0.15–0.50。
  唯一失败用例 500 ksps（SPS=2）误差 −48%，但自报 LOW 置信度（6.4 dB），行为正确。
- **BPSK 解调：3 个用例全部 100.00% 比特准确率，BER 0.0000**，且使用的是「检测出的」符号率
  而非真实值，属于真实端到端结果。
- **QPSK 解调：已通过验证，5/5 用例 100.00%，BER 0.0000，EVM 4.4–18.0%。**
  起初卡在 ~50%，两个独立原因，都已定位：
  1. `sigma_demod.py` 里用 `x^n` 均值相位做相位校正，残余 −41.5°，把符号转到错误轴上。
     改为「旋转搜索」：在粗估相位附近按星座对称性生成候选偏移，取星座拟合误差最小者。
  2. **真正的 50% 元凶在测试脚本而非解调器**：`verify_demod.py` 用独立随机比特生成 QPSK 符号，
     隐含的比特标注约定与解调器 `const` 数组不一致（Gray vs binary），导致恒定 50% 错。
     改为按星座索引生成符号 + 推导期望比特后即 100%。
     `diag_qpsk_err.py` 证明了星座索引映射本身完全正确（tx idx 0 → 0，85 次全对）。

### 已尝试但**失败**的方案（重要，勿重蹈覆辙）
低 α（0.20）时包络谱接近平坦，「最强 bin」不再可靠，会锁到噪声。我尝试用
**零 ISI 零陷（zero-ISI null）**作为物理判据来挑选正确候选，测了 4 种变体，结论是：
- 在**真实符号率**处，零陷对比度确实显著为正（+0.08…+0.21），非符号周期处 ≈0。
- **但这只能用于「确认某个已选定的周期是符号周期」，不能用于「搜索」符号率。**
  在频带内任意频率上扫，无关周期（81k、121k、65k、24.9k）也会偶然出现正对比度。
- 定量结论（`diag_score_select.py`，20 用例）：
  **用对比度打分挑选 = 11/20 正确；直接取最强 bin = 14/20 正确。对比度法更差。**
- 另外 `SPS` 与 `2·SPS` **都是真正的符号对齐周期**（每两个符号取一个仍然落在符号点上），
  且 `2·SPS` 的零陷还略深，所以零陷深度**无法**区分二者；这个选择只能由包络谱给出。
- 曾用「取最低的通过候选」规则，导致**全部用例减半**（回归）。
最终决定：**移除全部 ISI 判据代码**，恢复到简单且已验证的包络谱方案（`sigma_symbol_rate.py` 241 行）。
低 α 用例继续报 `NO DEMOD`——这是诚实的拒绝，不是错误结果。要修它们需要
匹配滤波后的判决反馈或真正的定时误差检测器（Gardner/M&M），而非包络谱技巧。

### 重要发现（对团队有价值）
1. **⚠️ Radioconda 的 numpy 2.2.3 里 `np.fft.rfft` 对复数输入完全不可用**，连
   `np.fft.rfft(np.ones(1024, dtype=np.complex128))` 都抛
   `TypeError: ufunc 'rfft_n_even' not supported for the input types`。
   实数输入正常。**复数输入必须改用 `np.fft.fft` 取前半谱。**
   现有代码恰好都安全（`sigma_symbol_rate.py:148` 喂的是 `np.abs(x)**2`，实数）。
   另一个坑：这个 numpy 上 `complex128 ** 2` 也会丢掉复数 dtype，需用重复相乘。
   开发机（numpy 2.5.3）不报错，**只在用户的 Radioconda 上炸**——所以必须用
   `C:\Users\sahil\radioconda\python.exe` 验证，不能用托管 Python。
2. **现有数据集文件是合成信号，没有可恢复的符号时钟。** 三个文件的 x^4 谱峰都精确落在
   f_s × 0.4 = 400 kHz（过于整齐），且不随内容变化，不符合任何真实脉冲成形特征。
   三个真实文件在估计器里都只报 LOW 置信度。
3. **已修复：`sigma_analyzer_core.py` 的调制分类器硬编码文件名分支。**
   原代码检查文件名含 "bpsk"/"qpsk"/"fm"/"rds"/"audio" 就返回硬编码置信度
   （"96.4%"/"94.8%"/"92.1%"），且**遮蔽了下方所有真实测量**（`d_phase`/`f_std`/`amp_std`
   算了却不用）。改成：
   - 新增 `_detect_psk_order()`：用 2 次方 / 4 次方载波线强度比来**测量** PSK 阶数。
     对已知真值验证 **11/12 正确**（BPSK 6/6 全对；唯一失败返回 0「无法判定」而非给错答案）。
   - 置信度字符串改为 `"measured"` / `"indeterminate"` / `"filename hint, unverified"`，
     不再是伪造的百分比。
   - 文件名只作**兜底提示**，且仅在测量无法判定时使用，并明确标注未经验证。
   - 已证明：把 `bpsk_modulated_1msps.iq` 改名成 `anonymous_capture.iq` / `random_data.iq`，
     结果仍是 `BPSK | measured`（改名前会掉到 `Digital PSK/FSK / 78.4%`）。
4. **采样率仍是文件名猜测**（`sigma_main_window.py` 的 `_load_signal_file`，匹配 "250k"/"1m"）。
   符号率与解调都依赖 f_s，这个上游捷径会影响所有下游指标。**尚未修。**

## 解调门限修正：组合标签不再被字符串黑名单拒绝

`_run_demod_stage()` 原先用 `if "BPSK" in mod or "QPSK" in mod` 做支持性判断。
分类器在 `amp_std < 0.12 and f_std > 0.4` 时会输出 **`"BPSK / 2-FSK"`**——
这正是 BPSK 的特征（恒包络 + 差分后相位方差大），而 `"BPSK" in "BPSK / 2-FSK"`

改为按序判定并显式区分：

```python
mod = m.modulation_class or ""
if   "QPSK" in mod: label = "QPSK"      # 必须先测 QPSK
elif "BPSK" in mod: label = "BPSK"
elif "PSK"  in mod: UNSUPPORTED          # 8PSK / Digital PSK/FSK
else:               UNSUPPORTED          # CW / AM-ASK / 未知
```

## 概念讲解：SPS / 载波恢复 / RRC 匹配滤波（回答 Sahil 提问）

用代码实际常量讲解，非泛泛教材内容。

### SPS（每符号采样点数）
= `f_s / R_s`，纯比例，**不携带新信息**。两个关键点：
1. **它是给 CNN 的好特征**，因为它是「比值」——`R_s` 以 Hz 表示会随 `f_s` 的猜测
   而错，但 SPS 由同一份数据的两个量相除得来，**不会继承 f_s 的错误**。
   这正是文档里推荐「喂 SPS 不喂 raw IQ」的深层原因。
2. **它决定是否够分辨率解调**。代码硬门限 `if sps < 2.0` 直接拒绝。
   500 ksps 用例失败的真因：@1 Msps 时 SPS≈2，估计器锁到 259.77 ksps（SPS=3.85），
   时钟线仅 6.4 dB 高于底噪 → LOW。

### 载波恢复（`estimate_carrier_offset`）
原理：PSK 信号取 M 次幂可**抹掉调制**，留下 4×offset 的纯音。
- BPSK 符号 ±1 → 平方后都是 +1（相位抵消）→ 用 M=2
- QPSK 符号 ±1±1j → 必须 **4 次幂**才能把四点塌缩到一点
代码要点：
```python
fourth = seg ** 4                      # modulation collapses
peak = freqs[argmax(abs(fft(fourth)))]
offset = peak / 4.0
span = samp_rate / 4.0                 # ★ 模糊折叠
while offset > span/2: offset -= span
```
★ 易漏：4 次幂谱线每 `f_s/4` 重复一次，真实偏移可能差一个 `f_s/4`，
必须折叠回合法范围。实测 demo 得 **+59,998 Hz** vs 生成时 60 kHz → 误差 2 Hz。

### RRC 匹配滤波（`_apply_matched_filter`）
解决 **ISI（码间干扰）**。名字里「匹配」就是全部含义：
**发射端用 root-raised-cosine，接收端用同一个**，两者卷积 = 完整升余弦，
其对符号时刻**零 ISI**（邻近脉冲恰好在采样点穿过零）。
这就是为什么两端都用 RRC 而不是一端用完整 RC。
- `alpha=0.35` 超额带宽；`span_symbols=8` 即 ±4 个符号的拖尾（图里的 smear）。
- `h /= sqrt(sum(h**2))` 能量归一化：让星座尺度可预测，
  使判决边界不随 sps/alpha 变化而失效。

### ★ 顺序不是任意的
载波恢复(1) 必须 **先于** 匹配滤波(2)：ISI 消除假设信号已在基带；
若还在 60 kHz 旋转，等于对旋转信号做匹配滤波，**匹配滤波性质不成立**。

### 3b 残差相位：不估计，改用搜索
不用符号统计去「估计」残差旋转——对称星座下该估计量会被**模糊本身**主导。
改为枚举星座对称群的候选旋转取最优（`score = rms distance to constellation`）。
这也是 BPSK 180° 模糊属「已知非 bug」的原因：搜索选一个确定性朝向。
**评分函数必须同样搜索旋转，否则测的是模糊而不是解调器。**

### 8PSK 根因：M 次幂的指数必须等于星座旋转对称阶数
`estimate_carrier_offset()` **把 `x**4` 写死了**。
- BPSK 2 阶对称 → 指数 2 即可（4 也算对，因为 4 是 2 的倍数）

| 信号 | x^2 | x^4 | x^8 |
|---|---|---|---|
| 2-PSK | **−2** | −2 | −2 |
| 4-PSK | +303 | **−2** | −2 |
| 8-PSK | −11111 | −16390 | **−2** |

规律清晰：**指数 = 星座阶数时误差恒为 2 Hz**（且更高次幂仍正确，因高阶是低阶的倍数）。

## Sanchit 两问：CNN 训练输入是什么 / 模型怎么处理（产出 CNN_INPUT_AND_TRAINING.md）

Sanchit 在群里问「model training input?」和「how we'll process model?」。
我没有只写文档——先**建了可运行的训练集生成器**，因为跑出来的数字才能回答这个问题。

### 关键发现 1（推翻了我们自己的文档！）
**`SPS` 不是调制方式的判别特征。** `L1_L2_L3_ARCHITECTURE.md` §4.1 与
`TEAM_TASKS.md` §4 原先都写「SPS 是最有信息量的特征」，**这是错的，已实测推翻**：
固定 R_s 时四种调制的符号率估计**完全相同**（100ksps 下全是 SPS=10.000），
因为包络时钟就在脉冲成形速率上，不含星座形状信息。这是**物理**，不是估计器弱点。

360 个样本上逐列打分（4 分类，随机基线 25%）：
```
locked              25.0%   随机
lock_confidence     26.9%   随机
prominence_db       25.0%   随机
samples_per_symbol  25.0%   随机
```
→ **四个标量全部等于随机。** 它们不是分类器，是**质量门控**（决定该不该信任图像）。
`SPS` 仍然必需——但它是喂给**解调器**的，不是喂给分类器的。
已修正三处文档中的错误主张，并加 WARNING 标注「此前版本的说法是错的」。

### 关键发现 2（我自己踩的坑，值得记）
**第一版训练集我只做到 25.3% = 随机，因为图像建错了位置。**
我最初按 SPS 抽取**原始样本**来画星座图 → 原始采集里还有 60kHz 载波偏移没去掉，
符号在旋转，星座图是一片**模糊的环**（~140 个非零 bin 铺满整格，max 0.023，
I/Q 质心四类全同 7.61/7.52）。没有任何可分类的东西。

**修正**：图像必须建自 **`demodulate().symbols`**（已完成载波恢复+匹配滤波+定时+相位校正）。
→ 25.3% 跃升到 **93.2%**。

**架构结论**：**CNN 必须跑在解调器前端之后，不能之前。**
Notion 流程图把分类器画在解调**之前**，对这个设计是反的。

### 最终实测（360 采集，分层 train/test，真实分类器）
```
constellation image only ................  93.2%
scalars only ............................  20.5%   (随机 25%)
scalars + image, block/global 标准化 .....  97.7%
```
各类召回：BPSK 90.9% / QPSK 100% / 8PSK 100% / 16QAM 100%
两次重跑**逐位一致**（可复现）。

**另一个自我纠正**：nearest-class-mean 基线显示「加标量把 67.8% 拉低到 26.4%」，
我一度以为标量破坏特征。用真实分类器后两种归一化顺序**都是 97.7%**——
原结论是弱基线造成的假象，不是缺陷，已在代码注释中更正。

### 环境现实（硬阻塞）
Radioconda 实测：numpy ✅ scipy 1.15.2 ✅ pandas 2.2.3 ✅，
但 **torch ❌ tensorflow ❌ sklearn ❌**，且**全仓库无任何训练代码/模型文件**。
